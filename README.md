# Ingress2Gateway Controller

[![Go Report Card](https://goreportcard.com/badge/github.com/eladmotola/ingress2gateway-controller)](https://goreportcard.com/report/github.com/eladmotola/ingress2gateway-controller)
[![CI](https://github.com/eladmotola/ingress2gateway-controller/actions/workflows/lint-and-test.yaml/badge.svg)](https://github.com/eladmotola/ingress2gateway-controller/actions/workflows/lint-and-test.yaml)

The `ingress2gateway-controller` is a Kubernetes operator that automatically and continuously converts standard **Ingress** resources into the modern **Gateway API** resources (`Gateway`, `HTTPRoute`, `GRPCRoute`, `TLSRoute`, and `BackendTLSPolicy`).

It bridges the gap between the legacy Ingress API and the powerful, role-oriented Gateway API, allowing you to migrate your traffic management at your own pace while maintaining a single source of truth.

## Why Ingress2Gateway?

*   **Automated Migration**: Stop manually writing Gateway API manifests. The controller does it for you.
*   **Continuous Synchronization**: Any changes to your Ingress resources are immediately reflected in the corresponding Gateway API resources.
*   **Provider Specific Logic**: Leverages the `ingress2gateway` library to support complex provider-specific annotations (e.g., Nginx, Istio).
*   **Infrastructure Agnostic**: Supports multiple Ingress controllers and Gateway API implementations.

## How it Works

The controller watches for `Ingress` resources that have the `ingress2gateway.io/gateway-class` annotation. When a change is detected, it performs the conversion and manages the lifecycle of the resulting `Gateway` and `HTTPRoute` resources.

## Supported Providers

The controller currently supports conversion from the following Ingress providers:

*   **nginx**
*   **ingress-nginx**
*   **istio**
*   **kong**
*   **gce**
*   **apisix**
*   **cilium**
*   **traefik**

## Supported Emitters

*   **standard** (default)
*   **envoy-gateway**
*   **gce**
*   **kgateway**

## Getting Started

### Prerequisites

*   Kubernetes 1.27+
*   Helm 3.0+
*   [Gateway API CRDs](https://gateway-api.sigs.k8s.io/guides/#install-gateway-api-crds) installed (>=1.5.0)

### Quick Installation

1.  **Install Gateway API CRDs**:
    ```bash
    kubectl apply -f https://github.com/kubernetes-sigs/gateway-api/releases/download/v1.5.0/standard-install.yaml
    ```

2.  **Install the Controller via Helm**:
    ```bash
    helm install ingress2gateway-controller oci://ghcr.io/eladmotola/ingress2gateway-controller \
      --namespace ingress2gateway-system \
      --create-namespace
    ```

## Configuration

The controller can select Ingresses either via annotation or by IngressClass, and can attach routes to either managed or external Gateways.

### Ingress Selection Modes

Configure via Helm value `controller.ingressSelectionMode` or CLI flag `--ingress-selection-mode`:

*   **`annotation` (default)**: Only Ingresses with `ingress2gateway.io/enabled: "true"` are converted.
*   **`ingressclass`**: An Ingress is automatically selected when its IngressClass (`spec.ingressClassName`, falling back to `kubernetes.io/ingress.class` annotation) is a key in `ingressClassToGatewayClassMapping` or `ingressClassToExternalGatewayMapping`. Ingresses whose class is not in either mapping are ignored (an `ingress2gateway.io/enabled: "true"` annotation does not force selection of an unmapped class).
*   **Opt-out**: In both modes, an explicit annotation `ingress2gateway.io/enabled: "false"` opts out of conversion.

> [!WARNING]
> **Finalizer Note**: In `ingressclass` mode, every selected Ingress receives the controller's finalizer (`ingress2gateway.io/finalizer`). Deleting those Ingresses will block while the controller is down or not running.

### External Gateways (`ingressClassToExternalGatewayMapping`)

If you have pre-existing Gateways managed by infrastructure teams or GitOps that the controller must not modify or delete, configure them via Helm value `controller.ingressClassToExternalGatewayMapping` or repeatable CLI flag `--ingress-class-to-external-gateway-mapping=<ingressClass>=<namespace>/<name>`.

When an Ingress targets an external Gateway:
*   The controller **never** creates, updates, or sets owner references on the Gateway.
*   The emitted Gateway is discarded and the controller only generates routes (`HTTPRoute`, `GRPCRoute`, `TLSRoute`).
*   Route `parentRefs` are set to the external Gateway's name and namespace, and `sectionName` is dropped (since listener names generated by emitters do not exist on the external Gateway).
*   Reconciliation converts only the reconciled Ingress, skipping the cluster-wide merge list.
*   The controller performs a best-effort check for the Gateway; if not found, it emits a Warning event and requeues after 30s while still creating the routes.

> [!IMPORTANT]
> **Listener Requirements**: The external Gateway's listeners must cover the necessary hostnames and allow routes from the Ingress namespaces (`allowedRoutes.namespaces`), otherwise Gateway API implementations will reject route attachment.

Example Helm configuration:

```yaml
controller:
  ingressSelectionMode: "ingressclass"
  ingressClassToExternalGatewayMapping:
    nginx-external: gateway-infra/shared-gateway
    nginx-public: gateway-infra/shared-gateway
```

### Global Class Mapping

When using managed (non-external) Gateways, you must provide a mapping between your Ingress classes and target Gateway classes:

```yaml
controller:
  ingressClassToGatewayClassMapping:
    nginx-internal: nginx
    nginx-external: nginx
```

### Controller CLI Flags

| Flag | Description | Default |
|------|-------------|---------|
| `--ingress-selection-mode` | Ingress selection mode (`annotation` or `ingressclass`). | `annotation` |
| `--ingress-class-to-external-gateway-mapping` | External Gateway mapping formatted as `IngressClass=namespace/name`. Repeatable. | (none) |
| `--source-provider` | Default source Ingress provider (e.g. `ingress-nginx`). | `""` |
| `--emitter` | Default emitter to use (e.g. `standard`). | `standard` |
| `--ingress-class-to-gateway-class-mapping` | Class mapping formatted as `IngressClass=GatewayClass`. Repeatable. | (none) |

### Ingress Annotations

| Annotation | Description | Default |
|------------|-------------|---------|
| `ingress2gateway.io/enabled` | Explicitly enable (`"true"`) or disable (`"false"`) conversion. | None (evaluated per mode) |
| `ingress2gateway.io/provider` | Source provider logic to use (e.g., `nginx`, `istio`). | Global default |
| `ingress2gateway.io/gateway-namespace` | Target Gateway namespace. | Ingress namespace |
| `ingress2gateway.io/emitter` | Emitter to use (e.g., `standard`, `envoy-gateway`). | Global default |

## Example

Annotate an existing Ingress to start conversion in `annotation` mode:

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: my-app
  annotations:
    ingress2gateway.io/enabled: "true"
spec:
  ingressClassName: nginx-internal
  rules:
  - host: my-app.example.com
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: my-app-service
            port:
              number: 80
```

The controller will automatically create a `Gateway` (if managed and doesn't exist) and routes (`HTTPRoute` / `GRPCRoute` / `TLSRoute`) pointing to `my-app-service`.
