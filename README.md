# Ingress2Gateway Controller

[![Go Report Card](https://goreportcard.com/badge/github.com/eladm/ingress2gateway-controller)](https://goreportcard.com/report/github.com/eladm/ingress2gateway-controller)

The `ingress2gateway-controller` is a Kubernetes operator that automatically and continuously converts standard **Ingress** resources into the modern **Gateway API** resources (`Gateway` and `HTTPRoute`).

It bridges the gap between the legacy Ingress API and the powerful, role-oriented Gateway API, allowing you to migrate your traffic management at your own pace while maintaining a single source of truth.

## Why Ingress2Gateway?

*   **Automated Migration**: Stop manually writing Gateway API manifests. The controller does it for you.
*   **Continuous Synchronization**: Any changes to your Ingress resources are immediately reflected in the corresponding Gateway API resources.
*   **Provider Specific Logic**: Leverages the `ingress2gateway` library to support complex provider-specific annotations (e.g., Nginx, Istio).
*   **Infrastructure Agnostic**: Supports multiple Ingress controllers and Gateway API implementations.

## How it Works

The controller watches `Ingress` resources according to its configured selection mode. When a change is detected, it performs the conversion and manages the lifecycle of the resulting `Gateway`, `HTTPRoute`, and `GRPCRoute` resources. The selection modes and environment-variable configuration are controller features and do not require changes to generated application Ingress manifests.

## Supported Providers

The controller currently supports conversion from the following Ingress providers:

*   **nginx**
*   **ingress-nginx**
*   **istio**
*   **kong**
*   **gce**
*   **apisix**
*   **cilium**
*   **traefik**

## Supported Emitters

*   **standard** (default)
*   **envoy-gateway**
*   **gce**
*   **kgateway**

## Getting Started

### Prerequisites

*   Kubernetes 1.27+
*   Helm 3.0+
*   [Gateway API CRDs](https://gateway-api.sigs.k8s.io/guides/#install-gateway-api-crds) installed (>=1.5.0)

### Quick Installation

1.  **Install Gateway API CRDs**:
    ```bash
    kubectl apply -f https://github.com/kubernetes-sigs/gateway-api/releases/download/v1.5.0/standard-install.yaml
    ```

2.  **Install the Controller via Helm**:
    ```bash
    helm install ingress2gateway-controller oci://ghcr.io/eladmotola/ingress2gateway-controller \
      --namespace ingress2gateway-system \
      --create-namespace
    ```

## Configuration

The controller supports annotation-driven selection for backwards compatibility, as well as deployment-wide selection for environments where application Ingress manifests are generated by tools such as GitLab Auto DevOps.

### Selection modes

Configure selection with `INGRESS_SELECTION` or `--ingress-selection`:

*   **`annotation`** (default): Only converts Ingresses with `ingress2gateway.io/enabled: "true"`.
*   **`mapped`**: Converts Ingresses whose `spec.ingressClassName` or legacy `kubernetes.io/ingress.class` value appears in the class mapping.
*   **`all`**: Converts every Ingress without requiring an opt-in annotation.

An explicit `ingress2gateway.io/enabled: "true"` or `"false"` annotation takes precedence over the selected mode. In particular, `"false"` remains an opt-out when using `INGRESS_SELECTION=all`.

When managing Gateways, `mapped` mode or `all` mode still requires an IngressClass-to-GatewayClass mapping for each selected Ingress. To convert Ingresses without maintaining that mapping, point the controller at an existing shared Gateway and set `TARGET_GATEWAY_MANAGE=false`.

### Mandatory Configuration

This configuration is required when the controller manages Gateways. You must provide a mapping between your Ingress classes and the target Gateway classes in your Helm values (`values.yaml`):

```yaml
controller:
  ingressClassToGatewayClassMapping:
    nginx-internal: nginx
    nginx-external: nginx
```

For a pre-existing shared Gateway, configure the target through environment variables or Helm values and disable Gateway management:

```yaml
env:
  - name: INGRESS_SELECTION
    value: "all"
  - name: TARGET_GATEWAY_NAME
    value: "external-gateway"
  - name: TARGET_GATEWAY_NAMESPACE
    value: "gateway-system"
  - name: TARGET_GATEWAY_MANAGE
    value: "false"
```

The controller will manage generated routes but will not create, update, or delete the external Gateway. Per-Ingress `ingress2gateway.io/gateway-name`, `ingress2gateway.io/gateway-namespace`, and `ingress2gateway.io/manage-gateway` annotations can override the global target settings.

### Required Annotations

| Annotation | Description |
|------------|-------------|
| `ingress2gateway.io/enabled` | Enable conversion for the Ingress. |

### Optional Annotations

| Annotation | Description | Default |
|------------|-------------|---------|
| `ingress2gateway.io/provider` | The source provider logic to use (e.g., `nginx`, `istio`). | Global default |
| `ingress2gateway.io/gateway-namespace` | The namespace where the `Gateway` resource will be created. | Ingress namespace |
| `ingress2gateway.io/route-namespace` | The namespace where the `HTTPRoute` or `GRPCRoute` resource will be created. | Ingress namespace |
| `ingress2gateway.io/gateway-name` | Target Gateway name. | IngressClass or global target |
| `ingress2gateway.io/manage-gateway` | Whether the controller manages the target Gateway. | `true` |

### Environment variables

| Environment variable | Description |
|----------------------|-------------|
| `INGRESS_PROVIDER` | Default source provider. `SOURCE_PROVIDER` is accepted as an alias. |
| `EMITTER` | Default emitter. |
| `INGRESS_SELECTION` | `annotation`, `mapped`, or `all`. |
| `INGRESS_CLASS_MAPPING` | Comma-separated `IngressClass=GatewayClass` pairs. |
| `TARGET_GATEWAY_NAME` | Shared or external Gateway name. |
| `TARGET_GATEWAY_NAMESPACE` | Shared or external Gateway namespace. |
| `TARGET_GATEWAY_MANAGE` | Whether the controller manages the target Gateway. |
| `LEADER_ELECT` | Enables leader election. `LEADER_ELECTION` is also accepted. |

Command-line flags take precedence over environment fallbacks. In a shared-Gateway conversion, routes retain each source Ingress's resolved `route-namespace`, so Ingresses from different namespaces can be merged without moving all routes into the namespace of the triggering Ingress.

## Example

Annotate an existing Ingress to start the conversion:

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: my-app
  annotations:
    ingress2gateway.io/enabled: "true"
spec:
  ingressClassName: nginx-internal
  rules:
  - host: my-app.example.com
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: my-app-service
            port:
              number: 80
```

The controller will automatically create a `Gateway` (if it doesn't exist) and an `HTTPRoute` (or `GRPCRoute`) pointing to `my-app-service`.
